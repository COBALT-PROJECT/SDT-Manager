#if you are using the alternative api call
Here's what a curl call to the `/create` endpoint should look like:

```bash
curl -X POST "http://localhost:8008/create?toeid=123456789&payload_type=BOMS" \
     -H "Content-Type: application/json" \
     -d '{
       "bomFormat": "CycloneDX",
       "specVersion": "1.4",
       "serialNumber": "urn:uuid:3e671687-395b-41f5-a30f-a58921a69b79",
       "version": 1,
       "metadata": {
         "timestamp": "2023-01-15T08:30:00Z",
         "component": {
           "type": "application",
           "name": "sample-application",
           "version": "1.0.0"
         }
       },
       "components": [
         {
           "type": "library",
           "name": "sample-component",
           "version": "2.1.0"
         }
       ]
     }'
```

Key elements of this curl command:

1. **HTTP Method**: `POST` to the `/create` endpoint
2. **Host and Port**: The example uses `localhost:8008`, which should be changed to match your server's address
3. **Query Parameters**:
   - `toeid`: Target of Evaluation ID (default is "123456789" if not specified)
   - `payload_type`: Type of payload (default is "BOMS" if not specified)
4. **Headers**:
   - `Content-Type: application/json` to indicate you're sending JSON data
5. **Request Body**: A valid CycloneDX JSON payload in the request body (this is just a sample - you should replace it with your actual CycloneDX data)

If you're calling the API from a different location, make sure to replace `localhost:8008` with the actual host and port where the SDT Manager is running.

Also, if you're using the alternative endpoint path shown in the code, you could use:

```bash
curl -X POST "http://localhost:8008/api/SDT/create/?toeid=123456789&payload_type=BOMS" \
     -H "Content-Type: application/json" \
     -d '{ ... your CycloneDX payload ... }'
```

Both endpoints should work identically since the `/create` endpoint redirects to the `/api/SDT/create/` endpoint in the fixed implementation.
